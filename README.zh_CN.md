# Pocket Finder —— AI Passport 的蓝牙场强探测玩法

本仓库托管 **Pocket Finder**：固件在 `feature/pocket-finder` 分支上，本页是它的说明。
它把 FoloToy AI Passport 变成一台**蓝牙接近度探测器**——扫描附近的 BLE 广播，显示每个信号的
强弱；你挑一个追过去，追到之后按一下换下一个。

固件**开机直接进入雷达页**——它就是本固件的产品界面，不用先在菜单里选。
基线测试菜单仍然可达：用退出动作（下键长按两次）即可回到菜单。

它是一个**玩法**，不是防丢器。在想让它帮你找某件特定东西之前，请先读下面的诚实声明。

## 它不做什么

- **它不识别你的设备。** 没有 MAC 匹配，也没有归属匹配。AirTag 与 Tile 出于反追踪设计
  会周期性轮换蓝牙地址与广播身份，第三方扫描器无法可靠地跟住它们。你能得到的是
  "这里有个设备，而且信号在变强"，永远不是"这就是你的钥匙"。
- **它不给方向。** ESP32-C3 是单天线、不支持到达角，方位在物理上无法获得。界面文案里
  没有任何方向性承诺。
- **它不报距离。** 只有相对信号强弱。任何绝对距离的说法（"1 米以内"）都被刻意去掉了。
- **它不用 NFC。** 板载是一颗被动 NTAG213 标签，没有面向 MCU 的接口：它只能被手机读取，
  自己读不了任何东西。

## 页面与按键

三个按键：上、下、确定（共用 GPIO0 上的一个 ADC 分压阶梯）。

**说明页** —— 每个固件版本显示一次。讲明点上的角度是随机的、不承载含义。只有"确定"能翻过。

**雷达页 RADAR** —— 一个环，最多六个点。每个点的**半径**编码信号强弱（越靠中心越强）。
每个点的**角度在本次会话内固定、且不承载任何信息**，它存在的唯一目的是让你能盯住同一个点。
环下方显示选中设备的名称与等级，底部有常驻提示 `ANGLE IS RANDOM / CLOSER/FARTHER IS REAL`。

| 按键 | 行为 |
| --- | --- |
| 上 / 下 短按 | 移动选中项 |
| 确定 短按 | 进入聚焦页 |
| 确定 长按 | 静音 / 取消静音 |
| 下 长按两次 | 退出本玩法（第一次长按只是武装确认层） |

**聚焦页 FOCUS** —— 只跟一台设备。五格信号条是主元素，下面是趋势词
（`STRONGER` / `WEAKER` / `STEADY`）与设备名。

| 按键 | 行为 |
| --- | --- |
| 确定 短按 | 切到下一个设备 |
| 确定 长按 | 静音 / 取消静音 |
| 上 长按 | 显示平滑后的 dBm 读数（诊断用） |
| 下 长按两次 | 返回雷达页 |

盖革计数器式的蜂鸣跟随信号等级：最弱时每 2500 ms 响一声，最强时收紧到每 80 ms 一声。
静音会保留视觉提示并停掉声音。

### 不按键的时候

屏幕不会一直亮着。停止按键 **1 分钟**后背光降到 **50%**，**3 分钟**后背光**全灭**
——面板仍显示最后一帧，只是不再发光。

按任意键即亮，而且**这一下只负责点亮屏幕**：不会顺手换设备或切换静音。同一次按压的抬起、
单击与长按事件会在 600 ms 内一并忽略，因此唤醒动作不会触发你看不见的操作。半亮状态下按键
照常生效。息屏期间扫描、设备老化与蜂鸣照常运行；退出玩法后背光恢复全亮。

## 诚实表达

因为没有身份匹配，界面永远不会宣称找到了**你的**东西。它只报告可测量的事实：
`NO SIGNAL`、`WEAK - TRY ANOTHER DIRECTION`、`GETTING STRONGER`、`VERY CLOSE - CHECK HERE`。
其中 "try another direction" 指的是**你自己**该换个位置或朝向，不是设备在哪个方向。

## 构建

按仓库自己的环境文档准备。简言之，在 ESP-IDF 5.5.3 已激活的前提下：

```bash
./tools/validate.sh          # 宿主测试 + 固件门禁
```

通过验证的合并镜像是 `build/FoloToy-AI-Passport-full.bin`，从 `0x0` 地址写入。
仅应用镜像 `build/FoloToy-AI-Passport.bin` 属于 `0x10000`，**不得**写到 `0x0`。
下面真机检查所烧录的镜像是 1,614,336 字节，SHA256
`2f37fe01886ebb28d7cbccfe27d51595a1bfb3e46110572bda37ee5de18f02a0`。

## 一处构建配置改动

`CONFIG_BT_NIMBLE_ROLE_OBSERVER=y` 是能扫描的前提；上游默认是 `n`。代价约为 4–8 KB Flash。
把它改回 `n` 即恢复"仅广播"的基线，此后本玩法无法扫描，雷达页会显示 `SCAN FAILED`。

本玩法自身不广播，所以"持续扫描挤占设备自身广播"这个常见顾虑在这里不成立。
扫描占空比（100 ms 间隔里开 40 ms 窗口）只是为了功耗。

## 240px 屏幕上的措辞选择

两处刻意偏离，都是被屏幕实际渲染能力逼出来的：

- 趋势用 `STRONGER` / `WEAKER` / `STEADY` 三个词，而不是箭头符号。本构建只启用了
  Montserrat 14 与 20，其字形覆盖不保证包含箭头；缺字形会渲染成空白框。
- 常驻提示是 `ANGLE IS RANDOM` / `CLOSER/FARTHER IS REAL`。整句在 14px 下约 243px 宽，
  会被 240px 的屏幕裁掉。

## 状态

构建与宿主测试已通过仓库门禁，合并镜像也已烧入真机。

已在硬件上验证（FoloToy AI Passport，ESP32-C3 revision v1.1，8MB Flash，无 PSRAM）：

- 合并镜像从 `0x0` 写入，回读哈希一致。
- 启动日志干净：显示、按键、音频、电池四项均就绪，NimBLE 扫描已启动，且雷达页打开期间
  设备停用了自身广播。
- 闲置阈值是从日志量出来的，不是靠眼睛看的：闲置 60.7 秒时背光降到 50%，闲置 180.8 秒时
  全灭，各自落在 1 分钟 / 3 分钟设定值的一个 100 ms tick 之内。
- 息屏后重新点亮已手动验证：按一下键屏幕就亮，且不会打乱玩法。

仍未验证：两个唤醒子情形未单独走过（息屏后第一次按压若长按 OK、以及从息屏状态退出玩法后
菜单的亮度），以及本版本的长时稳定性、续航、蜂鸣连续性、运行时内存余量，以及那个环会不会
真的把人误导到某个方向上走。
